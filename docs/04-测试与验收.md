## 1. 测试策略

### 1.1 测试金字塔

```text
                 ┌──────────────────────┐
                 │  手工验收 / 演示走查  │  ~15 条用例（TC-M）
                 ├──────────────────────┤
                 │  集成测试（DAO + 库） │  ~10 条用例（TC-I）
                 ├──────────────────────┤
                 │  单元测试（纯函数）   │  76 条自动化测试（含 DAO 集成），覆盖率目标 ≥ 80%
                 └──────────────────────┘
```

### 1.2 重点与原则

| 原则 | 说明 |
| --- | --- |
| 算法必须单测 | 紧急度、倒计时、成绩、提醒规划是"算错了没人看得出来"的地方，必须覆盖边界 |
| 时间必须可控 | 所有涉及"现在"的测试注入 `Clock.fixed`，禁止依赖真实时间 |
| 数据库必须隔离 | 每个测试用临时文件或 `jdbc:sqlite::memory:`，测试后清理，绝不碰 `data/coursework.db` |
| UI 不写自动测试 | 课程设计规模下 UI 自动化收益低，改用手工用例表 + 走查清单 |
| 缺陷可复现 | 记录精确到分钟的操作序列与日志片段 |

### 1.3 测试环境

| 项 | 配置 |
| --- | --- |
| 操作系统 | Windows 11（主），可选验证 Ubuntu 22.04 |
| JDK | 17（另用 25 编译验证兼容性） |
| 屏幕 | 1920×1080 / 125% 缩放，另测 100% 与 150% |
| 数据 | 空库、示例数据（8 门课 / 20 条作业）、1000 条压测数据 |
| 网络 | 断网（验证无网络依赖） |

### 1.4 执行方式

```bash

mvn test -Dtest=UrgencyCalculatorTest
mvn test jacoco:report              # 生成覆盖率报告 target/site/jacoco/index.html
```

## 9. 缺陷管理

### 9.1 级别定义

| 级别 | 定义 | 处理 |
| --- | --- | --- |
| S1 阻断 | 无法启动、数据丢失、崩溃 | 立即修，修完回归全部 ★ 用例 |
| S2 严重 | 核心功能不可用（如提醒不触发） | 当天修，补单测 |
| S3 一般 | 显示错误、交互不顺畅 | 本轮迭代内修 |
| S4 轻微 | 文案、间距、颜色 | 记录，M7 统一处理 |

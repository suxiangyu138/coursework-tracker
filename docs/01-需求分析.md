## 1. 背景与问题

### 1.1 真实场景

大三上学期共 12 门课，每门课 3–6 次作业，一学期累计约 50 个截止日。这些截止日的信息来源是分散的：

| 来源 | 典型形态 | 痛点 |
| --- | --- | --- |
| 雨课堂 / 学习通 | 平台内截止时间，需逐门课点进去看 | 不汇总，容易漏看新布置的作业 |
| 班级群 / 课程群 | 老师或助教发一条消息 | 消息被刷走，无法检索，时间常是"下周三之前"这种模糊表述 |
| 课堂口头通知 | "这个实验下周五交" | 当时记了，后来忘了记在哪 |
| 课程群文件 | 一份教学日历 Excel | 与实际调整不一致，且需要手动对照 |

### 1.2 现有工具的不足

| 方案 | 不足 |
| --- | --- |
| 手机备忘录 / 纸质清单 | 没有倒计时，不会主动提醒；不区分权重，无法判断先做哪个 |
| 日历 App（如系统日历） | 只能记录时间点，不知道作业是否完成、权重多少；不计算成绩 |
| 待办类 App（如 Todoist） | 需要联网、需要付费解锁提醒；无课程/学分/成绩维度 |
| 教务系统 | 只有成绩，没有过程管理；截止日提醒不可靠 |

### 1.3 核心矛盾

> **人在"要做的事"和"还剩多少时间"之间缺少一个实时的、量化的、会主动说话的视图。**

由此推导出产品的三个关键词：**汇总**（一个列表看全）、**量化**（还剩多久、占多少权重、做到几成）、**主动**（不用打开也知道）。

## 2. 目标与非目标

### 2.1 项目目标

1. **不漏交**：任何一条作业在到期前至少收到 1 次有效提醒，逾期未交持续可见。
2. **不瞎忙**：用可解释的紧急度评分告诉用户"现在该做哪一个"。
3. **心里有数**：随时看到总体/分课程的完成度与剩余工作量。
4. **算得清账**：知道当前加权得分、预计总评、目标分所需分数与预计 GPA。
5. **常驻可用**：托盘常驻、开机自启、离线运行，打开即用。

### 2.2 非目标（明确不做）

- ❌ 不替代教务系统：不抓取、不提交作业、不登录学校账号。
- ❌ 不做多人协作：单机单用户，无账号体系。
- ❌ 不做云同步：数据只在本机，隐私优先。
- ❌ 不做移动端：桌面常驻是核心形态。
- ❌ 不做作业内容管理：只记录元信息（标题、截止、权重、状态），不存附件正文。

### 2.3 约束条件

| 约束 | 说明 |
| --- | --- |
| 时间 | 课程设计周期约 2 周，实际可投入约 7 个工作日 |
| 技术 | 限定 Java 技术栈，需覆盖课程要求的知识点（见 05 文档） |
| 环境 | 演示环境为 Windows 10/11 + JDK 17；不得依赖联网服务 |
| 交付 | 源码 + 文档 + 可运行包 + 5 分钟答辩演示 |

## 3. 用户画像与典型场景

### 3.1 用户画像

| 维度 | 描述 |
| --- | --- |
| 身份 | 计算机相关专业大三学生 |
| 设备 | 笔记本电脑，Windows 11，每天使用 6–10 小时 |
| 课程量 | 一学期 10–14 门课，含 2–4 门专业课（权重大、作业难） |
| 痛点 | 作业多、来源散、临期焦虑、成绩焦虑 |
| 技术水平 | 能安装 JDK、会看日志、愿意手动录入数据 |
| 使用习惯 | 早上开机时看今日/本周待办；晚上写作业时看倒计时；期末查分前用成绩预估 |

### 3.2 典型场景

**场景 A · 周一早上开机**

> 电脑开机，任务栏右侧出现托盘图标，气泡提示："本周 5 个截止，最急：操作系统 实验三（还剩 30 小时）"。
> 点开主窗口，列表按紧急度排列，最上面三条标红。用户决定先做实验三。

**场景 B · 晚上写报告，差点忘记提交**

> 23:40，距离毛概读书报告 23:59 截止还有 19 分钟（处于 T-15min 档），托盘弹出提醒并播放提示音。
> 用户切到学习通上传文件，回到程序勾选"已完成"，列表沉底，完成率从 38% 变成 40%。

**场景 C · 期末前算成绩**

> 数据库课程已出 3 次作业分：85、92、78，权重各 15%（合计 45%）。用户在课程详情看到：已得加权分 38.25（折算百分制 85.0）、
> 若剩余 55% 按均分 85 计算，预计总评 85.0、GPA 3.7；想拿 90 分，剩余部分平均需要 94.1 分。

**场景 D · 换电脑 / 重装系统**

> 把 `data/coursework.db` 复制到新机器同一位置，打开程序，所有课程、作业、完成状态原样恢复。

## 6. 业务规则

| 编号 | 规则 | 理由 |
| --- | --- | --- |
| BR-01 | 权重取值范围 0–100；同一课程的权重之和允许不足 100 | 学期中作业未布置完是常态 |
| BR-02 | 截止时间精确到分钟，秒恒为 0 | 与教务系统一致，避免无意义精度 |
| BR-03 | 截止时间已过但未完成，状态仍可为 `TODO` / `DOING`，界面标记"逾期" | 逾期不等于放弃，用户仍可能补交 |
| BR-04 | 状态为 `DONE` / `SUBMITTED` 的作业不再触发任何提醒 | 避免打扰 |
| BR-05 | 修改截止时间后，删除该作业的 `reminder_log` 记录并重新排程 | 否则新时间点不会提醒 |
| BR-06 | 同一作业的同一提醒规则只触发一次（数据库唯一约束兜底） | 防重复通知，尤其重启后 |
| BR-07 | 静音时段内的提醒只落库不弹窗，恢复后合并为一条摘要 | 不打扰夜间休息，又不丢信息 |
| BR-08 | 统计与提醒只针对"当前学期未归档"的数据 | 归档数据不干扰现在 |
| BR-09 | 得分为空的作业不参与加权平均；权重为 0 的作业不参与权重完成度 | 避免除零与失真 |
| BR-10 | GPA 映射规则可配置，默认使用"标准 4.0"（见 02 文档 5.4） | 不同学校规则不同 |
| BR-11 | 倒计时格式：≥1 天 `3天 04:12:05`；<1 天 `04:12:05`；逾期 `逾期 2天 03:12`；已完成 `已完成` | 可读性与信息密度平衡 |
| BR-12 | 逾期判定以系统当前时间为准，允许用户机器时间不准确（不联网校时） | 离线优先 |

## 8. 数据需求

### 8.1 核心实体

| 实体 | 说明 | 预估规模 |
| --- | --- | --- |
| 课程 Course | 一门课程，含学分、教师、目标分 | 10–20 / 学期 |
| 作业 Assignment | 一次作业/实验/大作业，含截止时间与权重 | 30–100 / 学期 |
| 提醒记录 ReminderLog | 已触发的提醒，用于去重与补偿 | 100–500 / 学期 |
| 设置 Setting | 键值对配置 | < 30 项 |

### 8.2 数据保留与清理

- 作业删除时级联删除其提醒记录。
- 归档学期的数据永久保留，可手动删除。
- 日志单文件上限 5 MB，超出后重建，避免无限增长。
- 数据库体积预期 < 5 MB，无需分库分表。

### 8.3 数据质量要求

- 课程名唯一，防重复录入。
- 截止时间不得早于 2000-01-01、不得晚于 2100-01-01（防误输入）。
- 权重、得分、学分均为非负数值。
- 所有时间入库前统一为本地时区的 `LocalDateTime`，格式 `yyyy-MM-dd HH:mm:ss`（可字典序排序）。

## 9. 边界与异常场景

| 编号 | 场景 | 期望行为 |
| --- | --- | --- |
| EX-01 | 截止时间刚好等于当前时间 | 判定为逾期（`dueAt <= now`），不触发未来提醒；显示"逾期 0天"→ 统一显示"刚刚截止" |
| EX-02 | 截止时间为 23:59，提醒 T-15min 在次日 00:14 之前 | 正常触发（提醒时间可跨天） |
| EX-03 | 跨年作业（12-31 截止） | 倒计时与统计正常，不出现负数天 |
| EX-04 | 闰年 2 月 29 日 | 日期选择器可选，格式化正常 |
| EX-05 | 系统时间被修改（回拨/前进） | 提醒以新时间为准；已触发的记录不重复（唯一约束）；不崩溃 |
| EX-06 | 作业权重合计 > 100 | 允许保存但给出黄色警告"权重合计超过 100%" |
| EX-07 | 课程被删除但仍有作业 | 二次确认后级联删除；统计同步刷新 |
| EX-08 | 数据库文件被占用/只读 | 启动时捕获异常，提示改路径或关闭占用程序 |
| EX-09 | 托盘不可用（某些 Linux 桌面） | 降级为普通窗口模式，功能不受影响 |
| EX-10 | 提醒触发瞬间用户正在编辑对话框 | 不抢焦点，仅气泡提示；气泡点击后定位到该作业 |
| EX-11 | 一次扫描命中 10 条以上提醒 | 合并为一条摘要气泡，避免刷屏 |
| EX-12 | 用户点击"退出" | 先停止调度器、关闭数据库连接，再退出，避免半写状态 |

## 10. 成功标准

| 维度 | 标准 | 验证方式 |
| --- | --- | --- |
| 功能完整 | P0 需求 100% 实现，P1 至少 70% | 对照本文档 FR 表逐条勾选 |
| 提醒可靠 | 7 天连续挂机，所有到期作业均收到 ≥ 1 次提醒，无重复 | 日志核对提醒时间点 |
| 排序合理 | 与人工判断一致率 ≥ 90%（10 条样例） | 样例集人工比对 |
| 成绩正确 | 手算 3 个课程样例与程序结果一致（误差 < 0.01） | 单元测试 + 手工核算 |
| 稳定性 | 24 小时挂机无崩溃、无内存泄漏 | 挂机 + 任务管理器 |
| 体验 | 新建作业 ≤ 30 秒，答辩演示 5 分钟内跑完全流程 | 计时演练 |
| 文档 | 5 份文档齐全，与代码一致 | 自查 |

## 11. 范围外（Won't）

| 项目 | 原因 |
| --- | --- |
| 登录 / 多用户 | 单机工具，无账号需求 |
| 云同步 / 多端 | 增加复杂度与隐私风险，课程设计周期不够 |
| 教务系统抓取 | 涉及账号与爬虫合规，且不稳定 |
| 作业附件管理 | 文件管理与本工具定位不符 |
| 移动端 App | 桌面常驻是核心形态 |
| 自动识别群消息建作业 | NLP 工作量过大，风险高 |

## 12. 术语表

| 术语 | 含义 |
| --- | --- |
| 权重 | 该作业在课程总评中所占百分比（0–100） |
| 权重完成度 | 已完成作业的权重之和 ÷ 全部作业权重之和 |
| 紧急度 | 综合剩余时间、权重、预计耗时得到的 0–1 左右的可排序分数（逾期可 >1） |
| 视野窗口 | 计算紧急度时的时间归一化窗口，默认 168 小时（7 天） |
| 总评预估 | 已出分部分按实际分、未出分部分按预测分加权得到的课程总分 |
| 目标分反推 | 已知目标总评，反解剩余作业需要达到的平均分 |
| 标准 4.0 映射 | 90–100→4.0、85–89→3.7 … 的绩点换算表 |
